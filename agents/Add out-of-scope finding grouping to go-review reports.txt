Add out-of-scope finding grouping to go-review reports
*Description:*
Update go-review reporting so review findings that are valid but unrelated to the reviewed change are clearly distinguished from in-scope findings. The final report should preserve out-of-scope signal for awareness, but the verdict and main severity counts must be based only on findings caused or exposed by the MR, branch, or local diff.

*Implementation Details:*
* Add a final scope validation step after agent report deduplication and before report rendering.
* Classify every merged finding with `scope_status` (`in_scope` or `out_of_scope`) and `scope_reason`.
* Treat findings as in scope when they are on changed hunks, newly exposed by the change, tied to changed contracts/schema/config/deploy artifacts, required for safe deploy/rollback/mixed-version operation, or about tests for changed behavior.
* Treat findings as out of scope when they are pre-existing, independent from the reviewed change, and discovered only through exploratory context.
* Update report structure so Critical, Major, and Minor sections include only in-scope findings.
* Add an "Out Of Scope Findings" section grouped by severity and agent category.
* Update summary metrics to show `Critical (in scope)`, `Major (in scope)`, `Minor (in scope)`, and `Out of scope`.
* Ensure verdict rules ignore out-of-scope findings.
* Apply the behavior consistently to:
** `skills/go-review/workflow.md`
** `skills/go-review-branch/workflow.md`
** `skills/go-review-local/workflow.md`
** `skills/go-review-refs/report-format.md`
** `skills/go-review-refs/output-contract.md`
** `skills/go-review-refs/agent-output-schema.json`

*Definition of Done:*
* Report rendering contract documents that verdict and key production risks use only in-scope findings.
* Out-of-scope findings are preserved in a dedicated report section and still follow normal snippet/waiver rules.
* Shared schema allows optional `scope_status` and `scope_reason` fields without breaking existing sub-agent output.
* MR, branch, and local review workflows all include the final scope validation step.
* Documentation validation passes, including JSON schema parse and whitespace check for changed docs.

*Notes:*
This keeps review reports useful when agents notice adjacent problems, while preventing unrelated legacy issues from blocking the reviewed change.
